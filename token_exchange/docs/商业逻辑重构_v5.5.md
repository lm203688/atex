# ATEX 商业逻辑重构 v5.5
# 2026-05-17 基于竞品调研

## 竞品分析

### 1. Smithery（MCP托管平台）
- 模式：MCP Server托管 + 目录分发
- 定价：Hobby免费(50K RPC/月) → Pay as you go $10/月(100K RPC) → Custom
- 收入来源：MCP Server托管费（按RPC调用量）
- 关键：**他们自己不提供服务，只托管别人的MCP Server**

### 2. Composio（Agent工具集成平台）
- 模式：Agent集成工具层（250+工具/API连接器）
- 融资：$29M
- 收入来源：企业版订阅 + API调用费
- 关键：**他们提供的是"连接能力"，不是服务本身**

### 3. Nevermined（Agent支付协议）
- 模式：Agent间支付协议层
- 核心洞察：传统支付(Stripe $0.30/笔)不适合Agent微支付(平均$0.31/笔)
- 收入来源：支付手续费
- 关键：**他们解决的是支付管道问题，不提供服务**

### 4. 行业共识（2026）
- 纯订阅制对AI Agent不work（用量差异太大）
- 按次计费(Pay-per-use)是Agent经济的主流
- Agent间微支付需要新基础设施（传统支付太贵）
- **最有价值的是"自己提供服务让别人来买"**

## ATEX的核心问题

当前ATEX的问题：
1. **48个服务全是虚拟的** — 没有一个真正可执行（除了DeepSeek代理）
2. **没有自己的服务生态** — 平台只是个空壳市场
3. **用户来了没东西可买** — 注册后不知道干嘛
4. **Provider没有动力入驻** — 没有买家，谁来卖？

## 重构方向：先做自己的服务生态

### 核心思路：ATEX自己就是最大的Provider

**不要等别人来上架服务，自己先做10个真正可用的服务。**

参考Composio和Smithery的成功经验：
- Composio有250+工具 → Agent愿意接入
- Smithery有15,000+ MCP Server → Agent愿意来发现
- ATEX需要：**至少10个真正可执行的服务** → Agent愿意来消费

### 第一批自有服务（真正可执行）

| 服务 | 定价 | 后端 | 优先级 |
|------|------|------|--------|
| DeepSeek Chat API | ¥0.001/1K tokens | DeepSeek API | ✅ 已上线 |
| DeepSeek Reasoner API | ¥0.004/1K tokens | DeepSeek API | ✅ 已上线 |

| 语音合成(TTS) | 3 ATEX/分钟 | z-ai TTS | 🟡 高 |

**关键：这些服务全部用z-ai SDK作为后端，ATEX只是加价转售。**

### 商业模式：加价转售 + 平台佣金

```
用户付 → ATEX（加价30-50%）→ z-ai SDK（成本价）
用户付 → ATEX（佣金3-5%）→ Provider（服务费）
```

### 收入模型

| 收入来源 | 预估月收入(100用户) | 说明 |
|----------|---------------------|------|
| 自有服务加价 | ¥2,000-5,000 | DeepSeek/Web搜索/图片等 |
| 订阅费 | ¥1,500-3,000 | 30个基础版+5个专业版 |
| 充值余额沉淀 | ¥500-1,000 | 未消费余额 |
| 第三方Provider佣金 | ¥200-500 | 3-5%佣金 |
| **合计** | **¥4,200-9,500/月** | |

### 获客路径（参考Composio）

1. **MCP Server分发** — ATEX作为MCP Server上架到Smithery/Glama等目录
2. **开发者工具** — 提供免费Web搜索/图片生成等吸引开发者
3. **Agent间传播** — Agent用ATEX MCP工具后推荐给其他Agent
4. **GitHub开源** — 代码开源，文档引流

### 执行优先级

1. 🔴 **本周**：把Web搜索和网页阅读做成真正可执行的服务（用z-ai SDK）
2. 🔴 **本周**：ATEX MCP Server上架Smithery目录
3. 🟡 **下周**：图片生成/理解服务上线
4. 🟡 **下周**：TTS/ASR服务上线
5. 🟢 **两周内**：代码执行沙箱
6. 🟢 **两周内**：第三方Provider入驻流程优化
